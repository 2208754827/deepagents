# 跨节点共享术语表

parse / design / review 三节点必须按本表统一理解术语，禁止节点间语义漂移。

## 核心对象

- **测试用例（Test Case）**：单一可执行用例。必须含字段：用例标题、优先级、需求ID、设计方法、前置条件、步骤（操作+预期）、标签。一条用例 = 一个原子验证点。
- **测试场景（Test Scenario）**：相关用例的分组集合。一个场景下含 ≥1 条用例。场景本身不直接执行，执行的是其下属用例。
- **需求项（Requirement）**：需求文档中一个可独立验证的功能点，带需求ID（REQ-xxx / F1.2 / US_042）。一条需求应被 ≥1 条用例覆盖。

## 设计方法（design 节点 method 字段取值，固定缩写）

- **EP**：等价类划分。有效类合并为1条；每个无效类单独1条。
- **BVA**：边界值。上点/离点/内点各1条。
- **ST**：场景法。基本流 → 备选流 → 异常流。
- **EG**：错误推测。特殊字符 / 极端值 / 并发 / 空值等。

禁止 design 节点自造缩写；review 节点按此清单核验 method 字段合法性。

## 对象属性术语

- **业务规则（Business Rule）**：需求明确声明的约束（如"金额>0"、"仅管理员可操作"）。须落到 by_method 或专项用例。
- **约束（Constraint）**：对字段/流程的隐式限制（长度、类型、状态）。
- **边界值（Boundary）**：等价类交界处的取值点。
- **等价类（Equivalence Partition）**：输入域中被视为等价的子集，集合内任一值应触发相同行为。
- **派生字段（Derived Field）**：值由其他字段计算/推导得出的字段，须生成推导校验 + 编辑性控制用例。
- **状态机（State Machine）**：带状态流转的对象，须覆盖各状态的按钮活性 + 字段可编辑性矩阵 + 合法/非法转移。

## 质量度量（review 节点统一口径）

- **覆盖率**：covered_requirements / total_requirements，目标 ≥ 95%。
- **优先级分布**：P0 10-15% / P1 30-40% / P2 30-40% / P3 10-20%。
- **Scope 完整度**：需求涉及的子模块是否全部被用例覆盖，目标 100%。

## 禁止行为

1. parse 节点输出"测试场景"列表时，不得把单条用例误标为场景。
2. design 节点不得在 `用例标题` 用"正常"/"正确"作为修饰词，用"动作+对象+条件/场景"。
3. review 节点不得修改用例，仅产出检查报告。
